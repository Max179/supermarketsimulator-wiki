# supermarketsimulator.wiki

A source-only static site for the game **Supermarket Simulator** (documented build **1.6.0 (223)**), published at
<https://supermarketsimulator.wiki>. Pages are generated by a small Node builder from a normalized data index that is
committed to this repository. There is no framework, database or runtime service: the deploy target is a folder of
HTML, CSS, SVG and image files. Every URL the site prints — canonical, Open Graph, hreflang, JSON-LD, sitemap and
internal links — uses the clean form Cloudflare Pages serves (`/guide`, `/entries/<id>`), not the `.html` form that
Pages 308-redirects.

The output has two deliberately separate layers:

- **Player layer** — home, game guide, entity hub and category pages, entry pages, 77 guides, tools and updates.
  These are the pages a player is meant to find (211 indexable URLs, all in `sitemap.xml`).
- **Evidence layer** — class, namespace and data-name tables plus provenance, under `/reference/`, plus the
  11 picture-less subjects kept as notes. Marked `noindex` and excluded from the sitemap.

## Requirements

- **Node.js 22+** (the publish workflow uses Node 22). Build, tests and gates need no third-party packages.
- **Python 3** only for optional image tooling (`tools/image-sanity.py`, `tools/extract-images.py`), not for the
  build.
- No access to the game, no credentials and no network are needed to build or test the committed tree.

## Preview

```sh
npm run build
npx wrangler pages dev web/dist --port 4206
# open http://127.0.0.1:4206/   (clean URLs behave like production)
```

`npm run build` writes `web/dist/`, which is generated output and is not tracked by git. A plain static server (for
example `python3 -m http.server 4206 --directory web/dist`) also opens the site, but it only answers the emitted
`.html` file names; the clean URLs the pages link to are resolved by Cloudflare Pages (or `wrangler pages dev`).

| Command | What it does |
| --- | --- |
| `npm run build` | Regenerate `web/dist/` from `data/normalized/p0-inventory.json` and `content/`. Prints `pages=242 indexable=211`; the emitted files are still `.html`, the published URLs are clean. |
| `npm test` | Run the site gate suite (`tests/site.test.mjs`, 95 gates): builds into a temp directory and checks routes, clean URLs, canonical/sitemap equality, JSON-LD/social metadata, sitemap XML + truthful `lastmod`, robots.txt, IndexNow key, provenance, images, content invariants and the publish configuration. |
| `npm run gates` | Content gate, citation check, coverage matrix and image coverage; writes `reports/coverage-report.md` and `reports/image-coverage.md`. |
| `npm run classify` | Regenerate `config/urls.json` from a full `web/dist` build (one classification per emitted page). |
| `npm run preflight` | Publish checklist: runs the tests, requires a clean working tree, checks `reports/status.json`, the value layer, the handoff report, the workflow, the untracked raw/build boundaries and the coverage floor. |
| `npm run smoke` | Check the built artefact against the classified URL list. With a URL argument (`npm run smoke -- https://supermarketsimulator.wiki`) it checks the live site instead. |
| `npm run deploy-check` | Report local readiness and the external blockers (remote, Cloudflare secrets). |
| `npm run status` | Recompute `reports/status.json` from a fresh temp build plus git. |
| `npm run indexnow` | Submit the built sitemap's URLs to IndexNow (Bing/Yandex). Manual, post-deploy only — it is not part of the build, the gates or CI. `npm run indexnow -- --dry-run` prints the list. |
| `npm run typecheck` | `tsc --noEmit -p tsconfig.ci.json` — checks the `.mjs` builder and tests with portable type roots. |
| `npm run verify` | `npm test && npm run typecheck && npm run preflight` — the full local gate chain. It expects a clean tree, so run it after committing. |

`node pipeline/site.mjs` is the single build step. `pipeline/schema_to_inventory.mjs`, `pipeline/value_index.mjs`,
`pipeline/citation_index.mjs` and `tools/mac-package.mjs` are extraction-host tools: they need the raw decoded layers
that stay on the Windows machine, and they are never run by CI or by a Mac clone.

Typecheck (TypeScript is a devDependency; covers the builder and the tests):

```sh
npm install
npm run typecheck
```

`node_modules/` is ignored and must not be committed. The build and tests do not need it.

## Data boundary

- **Raw game files are not in git.** `data/raw/` is ignored; nothing under it is tracked. The repository ships only
  the normalized index, so a clean clone can build, test and gate the site without the game.
- **Regenerating the data requires Windows.** The extractors read a local Supermarket Simulator install
  (`Supermarket Simulator_Data/il2cpp_data/Metadata/global-metadata.dat`, sha256
  `acac0e03…`, 19,350,248 B, IL2CPP metadata v39) and the extraction scripts contain hard-coded Windows paths
  for that host. They need Python 3.12 with UnityPy for the asset side; the schema reader and the self-consistency
  probes are this repository's own scripts.
- **Therefore the normalized data is not reproducible on a clean Mac clone.** The committed indexes are the build
  input; re-extraction is a separate, host-specific step. This is a known and documented residual gap — see
  [`docs/data-pipeline.md`](docs/data-pipeline.md) and [`reports/data-boundary`](reports/archive-2026-09-28/data-boundary.md)
  for the exact paths, tool versions, byte-level anchors and open decoder work.
- **The decoded layers stay on the extraction host.** The 5,461,188 B field-row table and the 3,251,751 B type
  schema are replaced on this side by `data/normalized/value-index.json` (their counts and sha256) and
  `data/normalized/citation-index.json` (the names only they contribute). `tools/verify-citations.mjs` checks the
  same identifier universe on a light tree; `pipeline/status.mjs` records the derived value layer.
- **The one open decoder gap** is the type→field attribution: IL2CPP v39's field pointer inside the 82-byte type
  record has not been measured, so entries cite type names and asset names and never claim a field belongs to a
  class. That is the ceiling for this title, not a gap in the writing.

## Images and licensing

The site code is generated by this repository; it does not relicense any game asset:

- **In-game pictures** are official screenshots from the game's Steam store page and pictures shared by the community
  on the game's wiki sites (Fandom and wiki.gg). They remain the property of the game's developer and rights holders,
  or of the people who uploaded them to those wikis. Each is used only to identify the subject it illustrates: every
  mapped file is recorded in `content/images-manifest.json` with the source site, the page it was taken from, the
  date it was retrieved, the licence or rights-review status and the reviewer's verdict; the same verdict is written
  into `reports/image-reviews.md`. The file's dimensions, bytes and sha256 are recorded there too, so the copy served
  by the site can be re-checked against its record.
- **Every picture is credited.** The "Picture sources" section of `/reference/sources.html` is generated at build
  time from the manifest: one row per picture with its file, the entry it is used by, its source site, a link to the
  source page, its rights-review status and the date it was retrieved. A picture is never presented as official
  artwork or as an export from this machine.
- **Original diagrams** were drawn for this site and are always labelled as diagrams, never as screenshots.
- **A subject with no confirmed in-game picture is not published as an entry.** It is kept as a noindex note under
  `/reference/notes/` and labelled as such; a diagram never stands in for a screenshot.

The build needs no network: the pictures are committed with the manifest that documents them. The harvest, the
normalisation, the per-picture reviews and the raw textures they replaced are recorded in
[reports/image-replacement-2026-10-30.md](reports/image-replacement-2026-10-30.md).

If you are a rights holder and want a picture removed, use the contact page on the site.

## SEO and URLs

The site is built so search and social crawlers get one unambiguous version of every page. The full before/after
measurement is in [`reports/seo-audit.md`](reports/seo-audit.md); the rules are enforced by the test suite.

- **One URL form.** Cloudflare Pages serves `/x` from `x.html` and 308-redirects `/x.html`, so every URL printed
  by the build is the clean form: home is `/`, hubs are `/entities/`, `/articles/`, `/tools/`, everything else is
  `/path`. Canonical, `og:url`, both hreflang links, JSON-LD `url`/BreadcrumbList, sitemap `<loc>` and all internal
  links agree; the artefact still emits the same 242 `.html` files that Pages serves. `config/urls.json` is keyed by
  the clean URL.
- **Titles and descriptions.** Every indexable page has a unique title between 25 and 60 characters (primary keyword
  first; the ` · Supermarket Simulator Wiki` suffix is dropped rather than truncated past 60) and a unique
  description between 70 and 160 characters, cut at a word boundary. No page repeats the site name in its title
  twice, and nothing is truncated mid-word.
- **Sitemap.** `sitemap.xml` lists exactly the 211 indexable clean URLs. `<lastmod>` appears only where this
  repository records a real date — `content/updates.json` (`2026-10-01`, 9 pages) or `content/images-manifest.json`
  `retrievedAt` (`2026-10-30`, 108 entries plus the home page that shows their pictures). The 93 pages without a
  recorded date carry no `<lastmod>`; the build date is never used as a substitute.
- **Structured data and social.** Home ships `WebSite` + `SearchAction`; indexable pages ship `WebPage` or
  `Article` plus a `BreadcrumbList`, all pointing at the canonical. Article entries/guides carry headline,
  description, image (entries use their own in-game picture) and `datePublished`/`dateModified` only when a recorded
  date exists. Every indexable page has the full Open Graph block and a Twitter card; `twitter:image` equals
  `og:image`.
- **robots.txt** allows `/` and advertises the sitemap; the evidence layer stays `noindex, follow` and out of it.
- **IndexNow.** A public 32-hex key is committed in `web/assets/indexnow-key.txt` (and as
  `web/assets/<key>.txt`) so the build serves `/<key>.txt` from the site root. `tools/indexnow.mjs` submits the
  built sitemap to `api.indexnow.org`; run it by hand ```npm run indexnow -- --dry-run``` then ```npm run indexnow```
  after a deploy. It is not part of the build, the test suite or the publish workflow.

## Deploy

The canonical publish procedure is in [`reports/verification.md`](reports/verification.md). In short:
`.github/workflows/publish.yml` runs the gates and then deploys `web/dist` to the Cloudflare Pages project
`supermarketsimulator-wiki` on a push to `main`.

- CI gate job: build → site tests → typecheck.
- Deploy job (after the gate): build → `tools/preflight.mjs` → `tools/smoke.mjs` → `wrangler pages deploy`.
- After the deploy, verify the live URLs (`node tools/smoke.mjs https://supermarketsimulator.wiki`, which now checks
  each kept page's clean canonical) and then, if you want the engines pinged, run `npm run indexnow -- --dry-run`
  and `npm run indexnow`.
- Cloudflare Pages serves the clean URLs from the emitted `.html` files and 308-redirects the `.html` forms; no
  redirect rules need to be configured for that.
- DNS and custom-domain changes are dashboard actions, not part of the workflow.

## Secrets

The repository contains **no credentials, tokens or private keys**. Deployment uses the
`CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` GitHub repository secrets, injected at deploy time and never
written to a tracked file. Do not commit a token, an account ID or a local `.env`; preflight checks that the
workflow uses a secret rather than a literal token. The IndexNow key in `web/assets/` is a public ownership marker, not a secret.

2026-10-02 handoff package (`reports/handoff.md`, receipt `reports/mac-handoff-manifest.json`). The Mac side

in-game pictures and added the picture-provenance gate, converted every URL to its clean form and added the SEO
pass (titles, descriptions, sitemap `lastmod`, JSON-LD, robots, IndexNow key), and recorded the result in
[`reports/revival-2026-10-30.md`](reports/revival-2026-10-30.md) with the full verification log in
[`reports/local-complete.md`](reports/local-complete.md).
