# Image review log

Every image this site shows as a picture from the game is exported from this installation by
`tools/extract-images.py`, hashed when it is written, and listed with its origin in
`content/images-manifest.json`. This log records the separate, human step: opening the exported file and
checking by eye that it is a legible picture of the thing the entry says it is.

A picture fails the review if it is near-blank or featureless (a flat colour, an all-black or all-white
sheet, or unreadable stripes), or if what it actually shows is not the thing the note claims. A failed
picture is deleted together with its mapping and the manifest is regenerated; the entry then either gets a
different picture or is labelled as carrying an original diagram only. A verdict of "ok" means the file was
opened, compared against its note and its entry, and kept.

Transparent art is judged the way the page shows it: composited on the `#0f1116` background this site draws pictures
on, never flattened onto white. White-on-transparent art is the reason — the dashboard icons, the crosshair sheets,
the janitor and the petrol icon are all invisible when a viewer ignores alpha, and one of them was wrongly rejected
before this rule was written down. `tools/image-sanity.py` composites on the same background for the same reason. The
one case that cannot be fixed at review time is a mapping written as a JPEG: a JPEG cannot carry alpha, so the exporter
keeps whatever colour the texture stores under its transparent pixels, and those files must be judged on what the page
actually receives.

## Sanity pass before the eye check (tools/image-sanity.py)

`tools/image-sanity.py` measures every exported file first: it converts to greyscale, composites transparent pictures on the dark page background the site draws them on, and flags a file when it carries almost no variation (stddev below 12) or when more than 90% of its pixels sit within 6 of the median. The run for this build flagged 5 of 79 records:

- **floors-and-floor-painting-tiles.jpg** (stddev 11.1) — uniform by design: it is one ceramic tile pattern with a faint grout grid. Kept.
- **how-customers-find-their-way-sign.jpg** (stddev 5.0) — a faint walk-lane sign on grey; already logged above as readable. Kept.
- **restock-areas-and-vehicles-truck.jpg** (94% near-median) — a white UV layout with the truck's parts on it; the parts are visible. Kept.
- **serving-ice-cream-bucket.jpg** (97%) — the bucket is cream, so most pixels are close together, but the ICE CREAM labels are readable. Kept.
- **inside-a-vehicle-dashboard.png** (91%) — an icon sheet that is mostly empty because its art is one row of icons on a transparent field. Kept: on the dark page background the four icons read (see its row in the table).

An earlier run rejected `who-comes-into-the-shop-jacket.jpg` (stddev 3.1) — a flat dark navy sheet with nothing readable on it — and that entry was re-mapped to the game's own cloth sheet, which is the file the ledger row above records.

2026-10-01: `mapped/paper-bags-and-packing-a-purchase-bag.png` (`T_PaperBag_alb`, stddev 2.5) was **rejected after opening it**. The sheet is a near-uniform tan field with only faint horizontal streaks: it is the paper bag's colour map, so nothing on it identifies a bag and a reader would see a plain swatch. The mapping was deleted, the file removed, the manifest regenerated, and `paper-bags-and-packing-a-purchase` returned to `diagram-only`. No substitute was used, because every `T_PaperBag_*` texture in this build is a material map (normal, metallic-smoothness, ORM, or the same albedo) — there is no picture of a paper bag to map, so the entry is better served by its diagram.

The run is written to `reports/image-sanity.md` on every build; a flag is a request for a look, not a verdict.
