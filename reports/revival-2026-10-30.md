## 4. Change to the publish workflow (explicit, for the Lead to verify)

The package workflow ran `node pipeline/schema_to_inventory.mjs && node pipeline/site.mjs` in both the gate and
deploy jobs. After this integration the Mac tree no longer carries `data/normalized/p0-schema.json` (the decoded
type schema stays on the extraction host), so that command would fail in CI. Both build steps were changed to
`node pipeline/site.mjs` — **that is the only workflow change**. Kept exactly as before: the `needs: gate` deploy
dependency, the `node tests/site.test.mjs` gate, the typecheck step, `node tools/preflight.mjs`,
`node tools/smoke.mjs`, the `cloudflare/wrangler-action@v3` deploy with
`secrets.CLOUDFLARE_API_TOKEN` / `secrets.CLOUDFLARE_ACCOUNT_ID`, the Pages project name
`supermarketsimulator-wiki` and `--branch=main`.

## 5. Remaining blockers

1. **Push + live verification** — not done here by design: the Lead pushes; GitHub Actions then builds and deploys
   the 242-page artefact, and `node tools/smoke.mjs https://supermarketsimulator.wiki` confirms every kept URL
   live. The domain/Pages binding stays a dashboard action.
2. **Extraction-host-only steps** — `schema_to_inventory.mjs`, `value_index.mjs`, `citation_index.mjs`,
   `mac-package.mjs` and the Python image/localization extractors need the decoded layers and the installed game;
   they are correctly not run on the Mac. The committed indexes are the build input
   (`docs/data-pipeline.md` records the anchors).
3. **Type→field attribution** — unmeasured for IL2CPP v39; documented ceiling, not a writing gap.
4. **Newer game builds** — no extraction exists beyond `1.6.0 (223)`; a new package needs a Windows extraction run.
5. **AdSense** — the tree is policy-clean (About/Contact/Privacy/Terms/Disclaimer, no cookies/analytics, no ads,
   original writing) and records the policy checks, but no ad units are placed yet; that is an account-owner
   decision after the site is live and indexed.
